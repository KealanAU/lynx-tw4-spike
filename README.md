# Tailwind CSS v4 on Lynx: spike

This spike looks for the smallest Lynx layer needed on top of the official Tailwind v4 integration, [`@rsbuild/plugin-tailwindcss`](https://rsbuild.rs/plugins/list/plugin-tailwindcss). It accompanies [lynx-family/lynx-stack#69](https://github.com/lynx-family/lynx-stack/issues/69).

## Synopsis

Tailwind v4 runs on Lynx through the official plugin, with no new build integration. The Lynx layer is one CSS entry, a PostCSS plugin of about 100 lines, and four config settings. It needs no generated palette, because the plugin converts `oklch()` to hex. It targets SDK 4.2 and later, and older SDKs aren't supported. It would be a separate opt-in entry, so the v3 preset's SDK 3.2 baseline wouldn't change.

- **Works:** on the iOS simulator with Explorer 4.2.0, in dev and production, the page's tiles match their references apart from the failures below. That includes custom `oklch()` colours, an app's own `@theme`, `@plugin`, `@config`, `group-*`, `in-*`, `not-*`, 3D transforms, gradients, `inset-shadow-*`, `inset-ring-*`, `text-shadow-*` and `mask-[…]`.
- **Main finding:** `@layer` rules are silently discarded below SDK 4.2, and with `enableCSSRule` off the whole stylesheet is dropped with no warning. Most other failures come from `:root,:host` being dropped, and from the encoder removing properties v4 relies on.
- **Fails:** `first:`, `nth-*`, `has-*`, live `peer-*` updates, container queries, `starting:`, `hover:` on touch, `prefers-color-scheme`, `uppercase`, `ring-*`, `rebeccapurple` and `/opacity` on a colour that's only a `var()`. `space-x-*` only works in production, and `mask-none` hides the element. The plugin warns about the selectors, `@container`, `@starting-style` and the colours Lynx can't apply.
- **Not proven:** Android, a real device, and rendering of any value beyond this page's tiles. Row 49 only shows which properties survive encoding across the v3 matrix's families.

The first attempt is at the [`first-spike`](https://github.com/KealanAU/lynx-tw4-spike/tree/first-spike) tag.

Tested with rspeedy 0.18.2, `@rsbuild/plugin-tailwindcss` 2.0.3, tailwindcss 4.3.3, `@lynx-js/tasm` 0.0.49 and `@lynx-js/css-serializer` 0.1.9. Source was read at lynx-family/lynx `4.2.0` and `develop` (`ab7abc9`).

## Known failures

The warnings and selector removals marked as built are in `lynx-postcss.cjs` and were seen in the build output. The other options come from reading source and docs, and haven't been built or run.

| Failure | Cause | Recommended | Alternatives |
|---|---|---|---|
| `first:`, `nth-*` and other structural variants | The parser accepts them, but the matcher has no case, so they never apply. `not-first:` therefore always applies. No upstream work found | Use conditional classes in the app (`i === 0 ? 'a' : 'b'`). The plugin warns (built) | Upstream matcher support, roughly 100 lines plus tests, modelled on [lynx#5689](https://github.com/lynx-family/lynx/pull/5689). Sibling invalidation is the hard part. An encoder warning for selectors that can never match |
| `has-*` | The encoder rejects `:has()`, and there's no matcher or invalidation support. One `:has()` also takes down every selector merged into its rule (row 36) | The plugin removes that selector and warns (built) | Upstream parser, matcher and invalidation support, which is a large change |
| Live `peer-*` updates | `peer-[.on]:` matches, but `SupportedRelation` leaves out sibling combinators, so pressing the peer doesn't restyle its sibling | Document it | Add sibling combinators to invalidation upstream |
| Container queries | `core/renderer/css` has no `@container` support, and styles would depend on layout | The plugin warns (built) | Engine support |
| `starting:` | `core/renderer/css` has no `@starting-style`, and there's no build-time equivalent | The plugin warns (built) | None found |
| `hover:` | Tailwind wraps it in `@media (hover: hover)`, which only passes if the platform reports hover. It didn't fire on the simulator | Use `active:` on touch, as on the web | None needed |
| `group-disabled`, `group-data-*` | The matcher only handles `:hover`, `:active`, `:focus`, `:not` and `:root`, and has no attribute case. Not run | Port v3's class-based `group-ui-*` to v4 | Upstream matcher support |
| `mask-none` | Lynx hides an element with `mask-image: none`, even inline, where the web leaves it visible | Exclude with `@source not inline("mask-none")` | Upstream fix |
| `bg-linear-*/oklch` | The `@supports` block holding the interpolation mode doesn't apply, so it silently renders as sRGB | Document it | None needed |
| `dark:` | Explorer never calls `updateColorScheme`. Apps that call it should get working `dark:` with `enableCSSRule` on; not run | Keep Tailwind's media default and document `updateColorScheme`. Offer `@custom-variant dark (.dark &)` as opt-in, since Lynx has no agreed class or prop name | Explorer gets it on `release/4.4`. A cherry-pick to 4.3 would be sooner |
| `uppercase` | Lynx has no `text-transform`, and its docs list it as unsupported | Exclude with `@source not inline("uppercase lowercase capitalize")` and use `.toUpperCase()` in JS | None found |
| `ring-*` | v4's `box-shadow` list has variables with no defaults, because `@property` isn't supported | Add width, colour and shadow variables to the `*` reset, with `ring-*` and `shadow-*` writing the same `box-shadow` | Leave it out, as v3 does |
| `space-x-*` | Nested `calc()` is rejected in dev, and `:not(:last-child)` matches every child | In the PostCSS plugin, turn inner `calc(` into `(` and rewrite to `> * + *` | Upstream nested `calc()` and `:last-child` support |
| `/opacity` on a colour that's only a `var()` | With `@theme inline { --color-x: var(--x) }`, Tailwind can't resolve the colour, so `bg-x/50` falls back to `var(--x)` with no alpha, and its `color-mix()` sits in `@supports`. It renders solid | Put colours that need `/opacity` directly in `@theme`. The plugin warns (built) | Upstream `@supports` and `color-mix()` support |
| `rebeccapurple` | The only CSS colour name missing from Lynx's keyword table at 4.2.0. With `/opacity` it works, because Tailwind resolves it to hex | Use `#663399`. The plugin warns (built) | Add the keyword upstream |

A live global props update can be tested on unmodified Explorer 4.2.0: `NativeModules.ExplorerModule.saveThemePreferences('preferredTheme', 'Dark')` pushes new props to an open page. Reset it to `Auto` afterwards, because the value persists.

## Smallest setup

On top of `@rsbuild/plugin-tailwindcss`:

- `src/App.css`: the CSS entry, with `@utility` overrides. Its `runs/app.css` import stands in for an app's own theme and isn't part of the layer.
- `lynx-postcss.cjs`, loaded by `postcss.config.cjs`: converts `oklch()` to hex, rewrites the `:is()` and `:where()` selectors `group-*`, `peer-*` and `in-*` emit, removes selectors the encoder rejects, and warns about what Lynx can't apply.
- `lynx.config.ts`: `pluginTailwindcss({ optimize: true })`, `enableCSSRule: true`, `enableCSSInlineVariables: true` (row 48) and `enableCSSInheritance: true` (row 50).

`node lynx-postcss.test.cjs` checks the selector rewrite and the colour conversion, using `runs/palette.css` as the fixture.

## Preset shape

A CSS entry looks like `src/App.css`: no preflight, no `layer()`, plain line heights and transform steps, and `@utility` overrides. An app's own theme has three rules to follow: avoid `calc()` in values (rows 11 and 27), avoid `@theme inline` for colours that need `/opacity` (rows 9 and 52), and write `oklch()` with literal numbers so the plugin can convert it. Negative transforms, `scale-x-*`, `scale-y-*`, `border-x-*`, `border-y-*`, `inset-x-*`, `inset-y-*` and ring aren't included yet. Rendering has been checked on this page's tiles, while row 49 covers what survives encoding across the [v3 matrix](https://github.com/lynx-family/lynx-stack/blob/main/packages/tailwind-preset/docs/tailwind-css-v3-support.md)'s families.

v4 has no `corePlugins`. Unsupported built-ins can be stopped in three partial ways:

- The encoder already removes unsupported properties, so most built-ins are dead code plus a warning on the `enableCSSRule` off path.
- `@source not inline()` removes exact candidates, which suits variants and fixed names but not arbitrary values.
- `--namespace-*: initial` removes themed values only.

## Decisions for the maintainers

- **`rem`:** Lynx's `1rem` is 14px, so the default scale is 12.5% smaller than web. Keeping it matches the platform and the v3 preset's unit; rewriting the theme to pixels or web sizes would match Tailwind designs. Neither was chosen here.
- **`dark:`:** `prefers-color-scheme` is standard but stays light until hosts call `updateColorScheme`, and released Explorer doesn't. A class works today but needs a prop from each host, and only updates if the host pushes changes.
- **Structural variants:** `first:` and similar compile with no warning and never apply. Leaving them keeps the API and fails silently. `@source not inline()` can exclude exact classes but not a whole variant. Runtime support would fix them properly.

## The 2026-10-19 draft

- **Keep:** the entry shape in `v4.css` without preflight, the `@utility` transform set, the inlined shadow scale, and the compile-based test in `v4.test.ts`.
- **Drop:** `rsbuild.ts` and `loader.ts`, because `postcss.config.cjs` runs after Tailwind with no bundler hook (row 18).
- **Recheck:** the `postcss.ts` comment that Lynx "never applies" `@layer` rules is true on SDK 4.0 but not by source on 4.2.0 (row 2). Its selector filter misses `:is()`, and its `oklch` regex misses a hue of `none`. Layer unwrapping and `calc()` folding weren't needed, because no `layer()` and plain steps cover them.
- **Keep, with that fix:** `oklchToHex`, which `lynx-postcss.cjs` reuses because an app's own colours need it.
- **Keep, moved out of `@layer`:** the `*` transform defaults. Without them children inherit their parent's transform (row 28).
